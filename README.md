# 东亭诗社 · 作品页

一个静态诗词网站。**没有构建步骤**——`index.html` 既是源码也是成品，改完直接上传。

---

## 一、两个版本

| 目录 | 是什么 | 给谁看 |
|---|---|---|
| **`showcase/`** | **作品展示版**：只做主页展示，无编辑器、无详情页 | **交付给使用方的就是这版** |
| `full/` | 完整演示版：额外带登录/投稿、竖排书法、点字查字典 | 内部演示、功能参考 |

两版共享同一套视觉（宣纸底、社徽、配图），数据结构也一致。**改功能时注意别只改一边。**

## 二、跑起来

### 最简单
双击 `showcase/index.html`。绝大多数功能（展示、筛选、搜索、折叠）都能用。

### 但有两条功能在 `file://` 下会失效
浏览器出于安全会拦截本地文件的 `fetch` 和剪贴板：

| 功能 | `file://` 下的表现 | 影响 |
|---|---|---|
| **点字查字典**（仅 `full/`） | 提示「字典没加载出来」 | 页面已做兜底提示，不是 bug |
| **复制按钮** | 显示「复制失败」 | 同样有明确反馈 |

要测这两条，起一个本地服务器：

```bash
cd showcase        # 或 full
python -m http.server 8000
# 然后浏览器打开 http://127.0.0.1:8000/
```

## 四、三件必须记住的事

### 1. 换了内容，要重跑两个脚本 ⚠️

字体和字典都是**按当前页面出现的字**做的子集。**加了新诗、出现了新字，那个字会显示不出来**：

- 新字在书法竖排里 → **退回宋体，整篇混排**
- 新字点字典 → **「字典里没有这个字」**

```bash
node tools/subset-ink-font.py <字体.ttf>   # 重做书法字体子集
node tools/make-dict.js                    # 重做字典子集
```

细节见 [`docs/02-内容维护.md`](docs/02-内容维护.md)。

### 2. 不要把 API key 写进 `index.html`

`index.html` 是公开文件（部署后任何人可访问）。把 key 写进去 = 把账号密码贴门口。

`tools/liblib.js` 是从项目根目录的 `.secrets.json` 读凭据的——**那个文件不进仓库**（已在 `.gitignore` 里）。新成员要自己申请一份 key 填进去。

### 3. 图片是独立文件，漏传会「静默失效」

页面里的图片路径是 `images/art/xxx.webp`。**只上传 `index.html` 而不传 `images/`，图片会 404**——而且页面做了兜底：**加载失败时整块封面自动隐藏**，不显示破图。

所以表现是「诗还在、画没了」，**不报错、很难发现**。

上传前先跑一次：

```bash
node tools/check-dist.js      # 核对页面引用的每个资源是否都在包里，并扫描密钥
```

## 五、发布

站点是纯静态文件，任意静态托管都行。当前用的是 **GitHub Pages**（也试过 Netlify）。

**注意 GitHub Pages 的构建特性**：它是「提交后重新构建」才生效，且**一次提交 = 一次构建**。

- 只改 1 个文件 → 约 25 秒生效
- 一次提交 20+ 个文件 → 会触发 20+ 次构建，**其中若干次会 `errored`**，要等好几分钟

所以批量上传时用 `tools/publish.js`——它走 **Git Data API**（blobs → tree → commit → update ref），把整批文件做成**一次提交**：

```bash
# PowerShell：Node 取不到 gh 的输出（靠命名管道），所以由外面传进去
$env:GH_TOKEN = (gh auth token)

# 先干跑一遍，只看会提交哪些文件
node tools/publish.js --repo dongting-shishe --dir ../dist --dry

# 正式提交（整批一次提交，只触发一次构建）
node tools/publish.js --repo dongting-shishe --dir ../dist --message "更新配图"
```

它会自动跳过 `.git/`、`.secrets.json`、`.env`、`_build/`、`*.zip` 和下划线开头的临时文件。

## 六、已知限制（都是演示级，接后端时要处理）

| 项 | 现状 |
|---|---|
| 点赞 / 评论 | 只存在访问者自己的浏览器（localStorage），换人换设备各看各的 |
| 登录 / 投稿（`full/`） | 同上，且**不是真正的安全认证**，密码只做了一次摘要 |
| 配图 | AI 生成，有假印章/假题款的瑕疵 |
| 数据 | 全是示例数据（虚构诗 + 虚构作者名） |

接后端时，代码里已经预留了替换点：

```js
const Store = { /* 点赞、评论的读写 */ }    // → 换成接口请求
const WORKS = [ /* 作品数组 */ ]           // → 换成接口返回的数据
```

UI 与渲染逻辑不用动。
