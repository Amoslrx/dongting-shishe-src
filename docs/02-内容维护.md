改完内容到上线，按这个顺序走。

## 一、加了新诗 / 新作品之后 ★ 最容易埋的坑

**字体和字典都是「按当前页面出现过的字」做的子集。** 出现了新字就会出问题：

| 影响哪 | 症状 | 原因 |
|---|---|---|
| 竖排书法（`full/`） | 新字**退回宋体**，整篇混排 | 字体子集里没有这个字 |
| 点字查字典（`full/`） | 提示「字典里没有这个字」 | 字典子集里没有这个字 |
| 卡片标题/正文 | 正常 | 用的是系统字体，不受影响 |

所以每次加了新内容，**重跑这两个脚本**：

```bash
# ① 重做书法字体子集（需要一个 MaShanZheng 或 ZhiMangXing 的 ttf，见 03-素材与授权）
python tools/subset-ink-font.py <字体.ttf>

# ② 重做字典子集
node tools/make-dict.js --check      # --check 会打印多音字的分读音结果，便于抽查
```

两个脚本都是「扫 `index.html` → 抽出用到的字 → 生成子集」，输出会直接覆盖对应的文件。

> 想省事可以合并成一条命令，比如写个 `npm run rebuild`。

## 二、换配图

### 用 AI 生成
```bash
# ① 申请 LiblibAI 开放平台的 AccessKey / SecretKey，填进项目根目录的 .secrets.json
#    格式：{ "liblib": { "accessKey": "...", "secretKey": "..." } }
#    ⚠️ 这个文件不要提交到仓库

node tools/gen-art.js --list                    # 看会生成哪些
node tools/gen-art.js --only guanhe --count 2   # 先试一首
node tools/gen-art.js                           # 跑全部（失败会自动重试 5 次）
```

**注意平台不稳定**：实测约 1/4 的任务会返回 `[-1]执行异常`，脚本已内置重试，不用管。

提示词和挑图标准见 [`配图提示词.md`](配图提示词.md)。

### 换成人画的
直接把 `images/art/<slug>.webp` 和 `-thumb.webp` 替换成同名文件即可，不用改代码。

### 压成网页用的两档
```bash
# 桌面版长边 900 / 缩略图长边 460，自动出两档 WebP
python tools/make-art-webp.py
```

> 为什么分两档：列表只加载缩略图（11 张共约 170 KB），大图只在需要时才加载（约 450 KB）。

## 三、换社徽 / 换背景

```bash

python tools/make-seal.py <logo图片>

# 背景：改成合适尺寸的 WebP，放到 images/bg.webp 和 images/bg-mobile.webp
```

社徽的 base64 是**内联在 `index.html` 里**的（CSS 变量 `--seal-img`）。换社徽后要把新的 base64 替换进去，或者在代码里改成外链图片。

## 四、发布前必做

```bash
node tools/check-dist.js
```

它会做三件事：

1. **核对 `index.html` 引用的每个资源是否都在包里**（图、字典、字体……）
2. 列出包里存在但页面没用到的文件
3. **扫描密钥类文件**

**为什么必须做**：图片是独立文件。只上传 `index.html` 而漏了 `images/`，图片会 404 —— 而页面做了兜底，**加载失败时整块封面自动隐藏**，表现是「诗还在、画没了」，**不报错、极难发现**。

## 五、发布

### GitHub Pages 的构建特性 ⚠️
它是「提交后重新构建」才生效，而且**一次提交 = 一次构建**：

| 提交方式 | 结果 |
|---|---|
| 只改 1 个文件 | 约 25 秒生效 |
| 一次提交 20+ 个文件 | 触发 20+ 次构建，**其中若干次会 `errored`**，要等好几分钟，最后一次才成功 |

所以**批量上传时要合并成一次提交**（用 Git Data API：blobs → tree → commit → 一次 update ref），不要逐个文件 PUT。

### Netlify
支持拖拽整个文件夹上传，更简单。**注意只拖要发布的目录**（比如 `showcase/`），别把项目根目录拖进去——那里有 `.secrets.json`。

> 如果误传过整个项目目录，立刻去 `你的网址/.secrets.json` 确认能否访问；能访问就要去平台**重置 SecretKey**。

## 六、改代码时的几个约定

| 约定 | 原因 |
|---|---|
| **不要用数组下标当 ID** | 中间插一首新诗，所有点赞会整体错位挂到别人作品上。用 `code` |
| **正文高亮要走 DOM 文本节点** | 内容已经是 HTML，用正则包 `<mark>` 会把标签切开 |
| **折叠按实测高度** | 内容是 HTML，数行数算不准 |
| **用户输入一律过 `esc()`** | 评论、名字都是用户可控内容，不转义就是 XSS |
